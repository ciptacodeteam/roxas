Chapter 1

Getting Started

1.1 Logging In

The admin panel is accessible at /admin/login. Use your staff email address and password. After a successful login, you will be redirected to the dashboard.

  1. Navigate to https://<your-domain>/admin/login in your browser.
  2. Enter your email address and password.
  3. Click Sign In. Authentication is handled via JWT tokens stored in HttpOnly cookies — no further action is required.
  4. If you have forgotten your password, click Forgot Password? to receive a reset link by email.
ℹ️ Google Login
Admins may also sign in using a linked Google account if Google OAuth has been configured by the system administrator.
⚠️ Session Expiry
Access tokens expire after a short period. The system will attempt a silent refresh. If your session expires completely, you will be redirected to the login page.

1.2 Admin Dashboard Overview

After login you land on the Dashboard (/admin/). It provides a real-time (30-second cache) snapshot of the entire store.

📊 Overview Stats Cards

  • Total Orders (current vs. previous month %)
  • Total Revenue (IDR)
  • Total Registered Customers
  • Active Products

💰 Revenue Chart

  • Monthly revenue bar/line chart (full year)
  • Breakdown per month

📦 Order Status Breakdown

  • Count and total value (IDR) per status
  • PENDING, PAID, PROCESSING, COMPLETED, FAILED, REFUNDED, EXPIRED

🔌 API Health Status

  • Digiflazz connection status & current wallet balance
  • Midtrans connection status

📋 Recent Orders

  • Last 10 orders across all customers
  • Clickable rows link to order detail

🚨 Notifications

  • Failed transactions needing attention
  • Pending orders awaiting processing
  • New orders since last visit
💡 Tip
The dashboard refreshes its statistics every 30 seconds server-side. You can also hard-refresh the browser page to get the latest data immediately.

1.3 Admin Panel vs. Django Admin

Roxas Game Store has two admin interfaces:

InterfaceURLBest For
Next.js Admin Panel (primary)/admin/Day-to-day operations: orders, products, coupons, banners, users, analytics
Django Admin (advanced)/api/admin-portal/Low-level data edits, advanced filtering, email queue management, raw audit/API log viewing
⚠️ Caution
The Django Admin provides direct database access. Use it only when the primary panel does not expose the required control. Changes here may bypass business logic and validations.

1.4 Password & Account Settings

Access your own account settings at /admin/account/. Here you can:

  • Update your display name, contact phone, and profile photo
  • Change your password (requires current password)
  • View your account role (STAFF)

Chapter 2

Category Management

Categories are top-level groupings that organise products in the store (e.g., Mobile Games, Pulsa, PLN Prepaid). Navigate to /admin/categories/.

2.1 Creating a Category

  1. Click New Category (top-right button).
  2. Enter the Name. The slug is auto-generated (lowercase, hyphenseparated) but can be customised.
  3. Set Sort Order — lower numbers appear first in the store front.
  4. Toggle Is Active to make the category visible to customers.
  5. Click Save.
FieldRequiredNotes
Name✅ YesMust be unique across all categories
Slug✅ YesURL-safe identifier; auto-derived from Name
Sort Order✅ YesDefault 0; lower = displayed earlier
Is Active—Inactive categories are hidden from the storefront

2.2 Editing & Reordering Categories

Click any category row in the list to open the edit form. Change any field and press Save. To reorder, update Sort Order values and save each row.

🗑️ Deleting a Category
Deleting a category will cascade-delete all associated products and product items. Ensure all products are reassigned or deactivated first. This action is irreversible.

2.3 Instruction Images

Each category can have one or more instruction images — screenshots that guide customers on where to find their Game ID (e.g., how to locate a User ID in Mobile Legends). These appear on the product detail page.

  1. Open a Category (edit form).
  2. Scroll to the Instruction Images section.
  3. Click Add Image. Enter the Image URL, Alt Text (accessibility description), and Sort Order.
  4. Add as many images as needed, then click Save.

Product Management

Products represent individual games or services (e.g., Mobile Legends, Free Fire, PLN Prepaid). Each product has many Product Items (denominations). Navigate to /admin/products/.

3.1 Creating a Product

  1. Click New Product.
  2. Select the Category.
  3. Enter the Name and optional Description.
  4. Upload a Product Image (shown in the product card) and optional Banner Image (shown at top of product page).
  5. Choose an Input Field Preset (see Section 3.2) to auto-fill the input form configuration.
  6. Review/edit the generated Input Fields JSON if needed.
  7. Review/edit the Customer No Template (e.g., {userId}{serverId}) — this assembles the fields into the final game ID string sent to Digiflazz.
  8. Add Instructions text explaining how customers find their Game ID.
  9. Set Sort Order and toggle Is Active.
  10. Click Save.

3.3 Managing Product Items (Denominations)

Product Items are the individual purchasable denominations within a product (e.g., 86 Diamonds, 172 Diamonds). Navigate to /admin/product-items/.

Creating a Product Item manually

  1. Click New Product Item.
  2. Select the parent Product.
  3. Enter the Name (e.g., "86 Diamonds") and optional Group label (e.g., "Diamond", "Weekly Pass").
  4. Enter the SKU Code — this must match the buyer_sku_code provided by Digiflazz exactly.
  5. Set the Normal Price, optional Discounted Price, and Sell Price. Sell Price is what the customer will actually be charged.
  6. Toggle Is Active and Is Validation Item as needed (validation items are hidden from the storefront).
  7. Click Save.
ℹ️ Recommended: Use Digiflazz Sync
Rather than creating items manually, use Digiflazz Price Sync (Chapter 4) to automatically import all SKUs and their base prices. You will then only need to set the sell price.

Chapter 4

Digiflazz Integration

Digiflazz is the top-up provider that fulfils all game and digital product orders. The integration handles price syncing, transaction submission, and balance monitoring.

4.1 Price List Sync

Navigate to /admin/price-syncs/ (or the Django Admin under Price Syncs). The sync imports the full Digiflazz product catalog into your database.

Starting a Sync

  1. Click Trigger Sync.
  2. Choose the sync type:
    • PREPAID — prepaid products (game top-ups, pulsa, data)
    • PASCA — postpaid bills (PLN postpaid, PDAM, etc.)
    • FULL — both PREPAID and PASCA in one operation
  3. Optionally filter by Category or Brand to refresh only specific products.
  4. Click Start Sync. The task runs asynchronously — refresh the list to see the result.

Sync Behaviour

  • New SKUs are automatically created as Product Items and linked to the correct Product and Category.
  • Existing items' Base Price is updated from the Digiflazz data.
  • Sell Price is never overwritten — your margin is preserved.
  • Input field presets are automatically assigned to newly created products based on the Digiflazz category.
  • If a Category or Product does not exist yet, it is created automatically.
Column in Sync HistoryMeaning
Sync TypePREPAID, PASCA, or FULL
StatusIN_PROGRESS SUCCESS FAILED
Items SyncedTotal SKUs received from Digiflazz
Items UpdatedExisting items whose base price changed
Items CreatedBrand-new SKUs added to the database
Error MessageFirst 10 errors (if any)
Started At / Completed AtTimestamps

4.2 Balance Monitoring

The Digiflazz wallet balance is displayed on the main dashboard under API Health. The system automatically checks the balance on a scheduled basis.

  • If the balance falls below the configured DIGIFLAZZ_LOW_BALANCE_THRESHOLD, an alert email is sent to the ADMIN_ALERT_EMAIL address.
  • Monitor the live balance on the dashboard at all times — a depleted wallet will cause all top-up orders to fail.
  • Top up the Digiflazz wallet directly through the Digiflazz reseller portal.
🚨 Critical
If the Digiflazz balance reaches zero, in-progress orders will fail and customers cannot receive their top-ups. Always maintain a sufficient balance buffer, especially during peak hours.

4.3 Raw Price List Viewer

Navigate to /admin/digiflazz-json/ to see the raw JSON response from Digiflazz's price list API. This is useful for:

  • Verifying exact buyer_sku_code values before creating a product item manually.
  • Checking Digiflazz status (ACTIVE / INACTIVE) for individual SKUs.
  • Debugging sync discrepancies.

5.4 Handling Failed Transactions

When an order shows status FAILED, follow these steps:

  1. Open the order detail. Check the Failure Reason field and the Digiflazz Message field.
  2. Cross-reference with the Digiflazz portal to confirm the status there.
  3. Common causes:
    • Insufficient Digiflazz balance → top up your wallet and retry
    • Invalid customer number (game ID) → contact customer to verify their ID
    • SKU temporarily unavailable → contact Digiflazz support
    • Network timeout → the status checker will retry automatically for up to 90 days
  4. If the top-up cannot be fulfilled, process a refund (§5.5).
ℹ️ Automatic Retry
For PENDING Digiflazz transactions, the system automatically polls for status updates with exponential backoff. The process_order_topup task retries up to 5 times. Manual intervention is only needed for definitive GAGAL failures.

5.5 Refunds

Refunds are managed manually through the Django Admin or directly in the database, as Midtrans refunds depend on the payment method. To issue a refund:

  1. Initiate the refund on the Midtrans dashboard (for the applicable payment method).
  2. In the order detail (admin panel or Django Admin), update the order status to REFUNDED, fill in Refund Amount and Refund Reason.
  3. Contact the customer to confirm the refund timeline (typically 3–14 business days depending on payment method).
⚠️ No Automatic Refund
The system does not automatically trigger Midtrans refunds. This must be done manually through the Midtrans merchant dashboard.

Each payment method carries its own transaction fee and VAT that is added on top of the product price at checkout.

Chapter 7

Promotions

7.1 Coupons

Coupons provide discount codes that customers enter at checkout. Navigate to /admin/coupons/.

Creating a Coupon

  1. Click New Coupon.
  2. Enter the coupon Code (e.g., WELCOME10). This is case-insensitive from the customer's side; store it in uppercase by convention.
  3. Select Discount Type: PERCENTAGE (e.g., 10% off) or FIXED_AMOUNT (e.g., Rp 5.000 off).
  4. Set Discount Value (e.g., 10 for 10% or 5000 for Rp 5.000).
  5. Set Min Purchase — minimum order total for the coupon to be applicable (set to 0 for no minimum).
  6. For percentage coupons, set Max Discount — cap the maximum IDR discount (e.g., cap at Rp 50.000 even if 10% would be more).
  7. Set Usage Limit (total uses across all customers; leave blank for unlimited) and User Limit (per-customer uses; default 1).
  8. Optionally set Start Date and End Date for a validity window.
  9. Toggle Is Active and click Save.
FieldRequiredNotes
Code✅Unique; case-insensitive for customers
Discount Type✅PERCENTAGE or FIXED_AMOUNT
Discount Value✅% integer or IDR integer
Min Purchase✅0 = no minimum
Max DiscountPERCENT onlyCaps the discount in IDR (prevents over-discounting)
Usage Limit—Null = unlimited total uses
User Limit—Default 1 (each customer can use once)
Start Date—Null = active immediately
End Date—Null = never expires
Is Active—Must be active for customers to use it

Monitoring Usage

Click on a coupon row to see the Usage Count (auto-incremented). In the Django Admin, navigate to Coupon Usages to see which orders used which coupon, and the exact IDR discount applied.

7.2 Flash Sales

Flash Sales are timed discount events that make selected product items available at a special price with limited stock. Navigate to /admin/flash-sales/.

Creating a Flash Sale

  1. Click New Flash Sale.
  2. Enter a Name (e.g., "Weekend Special", "Harbolnas 12.12").
  3. Set Start Time and End Time (exact datetime with timezone).
  4. Toggle Is Active. The flash sale will only be shown to customers when both Is Active is true AND the current time is within Start–End Time.
  5. Click Save to create the flash sale event.

Adding Items to a Flash Sale

  1. Navigate to /admin/flash-sale-items/ or use the inline editor within the flash sale form.
  2. Click Add Flash Sale Item.
  3. Select the Flash Sale and then the Product Item.
  4. Set the Sale Price (the discounted price during the flash sale; replaces the item's regular Sell Price).
  5. Set Stock — the maximum units available at this flash sale price (e.g., 100). Set to a very large number if stock is effectively unlimited.
  6. Click Save.
FieldDescription
Flash SaleParent flash sale event
Product ItemThe specific denomination on sale
Sale PriceFlash sale price (must be lower than regular Sell Price to make sense)
StockTotal units available at the flash sale price
Sold CountAuto-incremented — how many units have been sold in this flash sale (read-only)
💡 Best Practice
Create the flash sale a few hours before start time, then set Is Active to true. This prevents the flash sale from appearing prematurely while you add items.

Chapter 8

Marketing Banners

Marketing Banners appear as a carousel/slideshow in the hero section of the homepage. Navigate to /admin/marketing-banners/.

Creating a Banner

  1. Click New Banner.
  2. Enter an optional Title and Description.
  3. Upload the Image (recommended dimensions: 1200×450 px, JPG or WebP for best performance).
  4. Enter an optional Link URL — the user is taken to this URL when clicking the banner (e.g., /product/mobile-legends or an external promotion page).
  5. Set Sort Order — lower number = displayed first in the carousel.
  6. Optionally set Start Date and End Date to schedule the banner automatically (leave blank to show indefinitely).
  7. Toggle Is Active and click Save.
FieldRequiredNotes
Image✅Recommended 1200×450 px; JPEG/WebP
Sort Order✅Lower = appears first in carousel
Link—Click destination; can be internal path or full URL
Start Date—Null = banner is immediately shown (once Is Active = true)
End Date—Null = banner never auto-hides
Is Active—Inactive banners are hidden from storefront regardless of dates
ℹ️ Scheduling Logic
A banner is visible to customers only when all three conditions are met: Is Active = true AND current date is ≥ Start Date (if set) AND current date is ≤ End Date (if set).

Ratings & Reviews

Customers can submit star ratings (1–5) and optional written comments for products after their orders are completed. Navigate to /admin/ratings/.

Moderation

Each review has an Is Active flag that controls whether it is shown publicly on the product page.

OrderLinked completed order

Actions

  • Deactivate a Review — click the review row, set Is Active to false, save. The review will no longer appear on the product page but is retained for audit purposes.
  • Reorder Reviews — adjust Sort Order values to pin specific reviews to the top of the product page.

💡 Review Policy
Only hide or remove reviews that violate community guidelines (spam, offensive language, irrelevant content). Hiding negative-but-genuine reviews can damage customer trust.

11.3 Email Queue

All outgoing transactional emails (order confirmations, password resets, welcome emails) pass through an async email queue. View it at /api/admin-portal/ → Email Queues.

Failed emails show the last error in the Last Error column. Common causes:

  • Invalid Resend API key or unverified sending domain
  • Recipient email address bounced
  • Celery worker not running (check server health)

Retrying a Failed Email

In the Django Admin, open the failed queue item and click Retry. Alternatively, use the API endpoint POST /api/v1/admin/email-queue/{id}/retry/.

ℹ️ Custom Templates
The Customer No Template is a Python str.format() string. You can combine multiple fields, e.g., {userId}|{serverId} or {zone}{userId}, depending on what Digiflazz expects for the specific product.
